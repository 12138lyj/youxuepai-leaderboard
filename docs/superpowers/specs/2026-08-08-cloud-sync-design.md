# 优学湃积分排行榜云同步设计

## 目标

将当前 GitHub Pages 静态排行榜接入 Supabase，使所有设备读取同一份班级数据。访客无需登录即可查看，教练输入统一管理密码后才能编辑。系统按单编辑者模型工作，不处理多人同时修改的字段合并。

## 已确认范围

- 原 GitHub Pages 网址和现有排行榜界面继续使用。
- 公开访客可以查看全部班级、学员姓名、积分、徽章和课程记录。
- 教练使用一个共享管理员账号和统一密码进入编辑模式。
- 多个已打开页面通过 Supabase Realtime 自动接收更新。
- 浏览器保留本地缓存，云端不可用时仍能展示最近一次数据。
- 初始云端数据为“暑假学习技能训练”班的 10 名学员，所有积分为 0。
- 不实现复杂的多人冲突合并，最后一次成功保存的数据生效。

## 技术方案

### 托管边界

- GitHub Pages：继续托管 HTML、CSS、JavaScript、Logo 和现有动画资源。
- Supabase Database：保存排行榜状态。
- Supabase Auth：验证共享管理员账号和密码。
- Supabase Realtime：通知在线设备读取最新状态。

网页只包含 Supabase 项目 URL、公开 anon key 和共享账号邮箱。它们是客户端连接配置，不是管理密钥。管理员密码、service role key 和其他私密凭证不进入 Git 仓库、网页源码或测试日志。

### 数据表

使用一张 `public.leaderboard_state` 表和一条主记录，保持与现有 `appState` JSON 数据结构一致：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `text` 主键 | 固定为 `main` |
| `payload` | `jsonb` | 经 `normalizeAppState` 规范化后的完整排行榜状态 |
| `revision` | `bigint` | 每次保存递增，用于识别新旧更新 |
| `updated_at` | `timestamptz` | 云端最后更新时间 |
| `owner_id` | `uuid` | 允许写入的 Supabase Auth 用户 ID |

整份状态单记录保存，原因是现有应用已经将班级、课程记录、学员和徽章作为一个原子状态管理，而且已确认通常只有一位教练编辑。这样可以避免拆表后产生跨表保存不完整的问题。

### 权限规则

在表上启用 Row Level Security：

- `SELECT`：允许 `anon` 和 `authenticated`，满足公开直接查看。
- `INSERT`：不向网页开放；首次数据由受控初始化脚本写入。
- `UPDATE`：仅当 `auth.uid() = owner_id` 时允许。
- `DELETE`：不开放。

网页不使用 service role key。即使访客查看源码获得 anon key，也只能读取，不能修改或删除数据。

## 客户端结构

新增独立云端模块，避免把网络、认证和 Supabase 细节继续堆进 `src/app.js`：

- `src/cloud-config.js`：Supabase URL、anon key、主记录 ID 和共享账号邮箱。
- `src/cloud.js`：登录、退出、读取、保存、重试和 Realtime 订阅。
- `src/app.js`：继续负责页面状态与渲染，通过云端模块提供的接口同步。
- `vendor/supabase.min.js`：固定版本的 Supabase 浏览器客户端，避免依赖运行时 CDN 波动。

云端模块只接收和返回普通对象。所有远端 `payload` 在进入页面状态前都必须经过 `State.normalizeAppState`。

## 数据流

### 页面启动

1. 立即读取本地缓存并渲染，避免空白页面。
2. 初始化 Supabase 客户端和同步状态提示。
3. 如果本地没有待上传修改，从云端读取 `main` 记录并覆盖本地缓存。
4. 如果本地存在已登录教练产生的待上传修改，先尝试上传，再读取云端确认结果。
5. 建立 Realtime 订阅，接收更高 `revision` 的状态。

### 登录与编辑

1. 未登录访客点击“课堂评分”时显示管理密码对话框。
2. 客户端使用配置中的共享账号邮箱和输入的密码调用 Supabase Auth。
3. 登录成功后打开原编辑抽屉，并显示“退出管理”。
4. Supabase 保存登录会话令牌，但应用不保存明文密码。

### 保存与广播

1. 编辑操作继续立即更新页面和本地缓存。
2. 保存进入短时间防抖队列，减少连续输入产生的请求。
3. 云端更新 `payload`、递增 `revision` 并刷新 `updated_at`。
4. 保存成功后清除本地待上传标记，状态显示“已同步”。
5. 其他设备收到 Realtime 事件，规范化数据后更新页面和缓存。
6. 本设备收到自己的回声事件时，根据 `revision` 忽略重复渲染。

## 界面行为

页面顶部增加紧凑的同步状态，不改变主要排行榜布局：

- `正在连接`：启动并读取云端。
- `已同步`：本地与云端一致。
- `同步中`：正在保存。
- `离线`：使用本地缓存，等待网络恢复。
- `同步失败`：保存未完成，保留本地待上传数据并自动重试。

未登录时页面保持完整可读。编辑按钮触发密码对话框；登录成功后保留现有编辑流程，并提供“退出管理”。登录失败使用明确但不泄露账号细节的错误提示。

## 错误与恢复

- 云端首次读取失败：显示本地缓存并进入离线状态，不阻塞查看。
- 保存失败：不撤销刚才的本地编辑，写入待上传标记并在网络恢复后重试。
- 远端数据格式无效：拒绝覆盖当前状态，显示同步失败并记录非敏感错误。
- 登录失效：关闭编辑权限，保留未上传本地修改并要求重新登录。
- Realtime 断开：自动重连；重连后主动读取一次主记录，避免漏事件。
- 恢复示例数据：仍需管理员登录，确认后作为一次正常云端保存广播。

## 测试与验收

### 自动测试

- 云端模块：读取、保存、登录、退出、重试、revision 去重和无效数据处理。
- UI：未登录不能编辑、密码登录后可编辑、退出后恢复只读。
- 同步：保存成功状态、保存失败待重试、Realtime 远端更新、本地回声去重。
- 离线：云端不可用时本地缓存正常显示，恢复后重新同步。
- 回归：现有段位、晋级动画、班级切换、累计积分和徽章测试全部通过。

### 线上验收

- 未登录设备可以直接打开排行榜，但无法写入数据库。
- 管理密码错误时不能进入编辑模式。
- 管理密码正确时修改积分，第二台设备无需刷新即可看到变化。
- 两台设备刷新后仍显示同一份数据。
- 临时断网后页面可查看缓存，并在恢复网络后完成待上传保存。
- GitHub 仓库和浏览器源码中不存在管理员密码或 service role key。

## 部署步骤

1. 创建 Supabase 免费项目。
2. 创建共享管理员 Auth 用户并记录其 UID。
3. 建表、启用 RLS、创建策略并开启 Realtime。
4. 写入当前 10 人初始记录。
5. 配置客户端公开连接信息，不提交私密凭证。
6. 完成自动测试和本地双页面同步测试。
7. 推送 GitHub Pages，验证公网读取、登录写入和跨设备更新。
