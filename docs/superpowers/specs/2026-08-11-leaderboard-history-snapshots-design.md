# 排行榜历史快照与版本恢复设计

## 目标

为优学湃积分排行榜增加云端历史版本能力，防止误重置或误修改造成数据永久丢失。

- 每次云端保存成功后自动生成一个完整网站快照。
- 每个排行榜记录只保留最近 50 个版本。
- 管理员可以查看历史版本并一键恢复整个网站状态。
- 恢复操作本身生成一个新版本，因此恢复后仍可撤回。
- 历史数据在所有设备间同步，普通访客不能查看或恢复历史。

## 已确认范围

- 快照频率：每次云端保存，不合并连续修改。
- 保留数量：最近 50 个版本。
- 恢复范围：完整 `payload`，包括所有班级、学员、积分、课次、徽章、荣誉记录、当前班级和晋级音效设置。
- 入口位置：管理模式的编辑抽屉内增加“历史版本”按钮和当前版本数量。
- 历史列表：按时间倒序显示版本号、保存时间、班级数、学员数、总积分和音效状态。

## 数据库设计

新增 `public.leaderboard_state_history` 表：

- `id bigint generated always as identity primary key`
- `state_id text not null`
- `owner_id uuid not null`
- `revision bigint not null`
- `payload jsonb not null`
- `created_at timestamptz not null`
- `unique (state_id, revision)`

表启用 RLS。只有 `auth.uid() = owner_id` 的管理员可读取历史；匿名用户无权限。网页不获得历史表的写入或删除权限。

在 `leaderboard_state` 上增加 `AFTER UPDATE` 触发器。触发器把更新后的 `payload` 和 `revision` 写入历史表，再删除该 `state_id` 超出最近 50 条的旧版本。迁移执行时先把当前云端状态补录为第一条历史快照。

恢复通过 `restore_leaderboard_snapshot(p_snapshot_id bigint)` RPC 完成。RPC 校验登录用户是排行榜所有者，读取指定快照并更新当前 `leaderboard_state`。更新会再次触发快照，因此恢复后的状态成为新的最高版本，恢复前状态仍在历史中。

## 网页交互

管理员登录后，编辑抽屉显示“历史版本”按钮。点击后打开历史版本面板：

- 顶部说明最近 50 个版本和整站恢复范围。
- 当前版本置顶，按钮显示“当前版本”并禁用。
- 其他版本显示“恢复此版本”。
- 点击恢复先弹出确认框，明确版本号、保存时间以及会替换的内容。
- 确认后按钮进入加载状态，禁止重复提交。
- 成功后使用 RPC 返回的完整状态刷新所有视图，并显示“已恢复到 vN，已生成新版本”。

版本行使用实际数据生成摘要，不生成可能误导用户的人工描述。版本标题格式为“第 N 节课 · 自动保存”；缺少课次时显示“自动保存”。

## 数据流

1. 网页继续使用现有 400ms 防抖保存流程。
2. `save_leaderboard_state` 更新当前状态并增加 `revision`。
3. 数据库触发器原子写入新快照并裁剪到最近 50 条。
4. 历史面板通过管理员会话读取最近 50 条快照。
5. 恢复 RPC 校验权限、写回完整快照并返回新的当前状态。
6. 网页规范化返回数据、更新本地缓存、重新渲染并刷新历史列表。

## 错误处理

- 未登录时不显示历史入口，也不请求历史数据。
- 网络失败、会话过期或快照不存在时不修改本地页面，显示可重试错误。
- 恢复 RPC 只接受数值快照 ID，不接受客户端提交的任意 `payload`。
- 触发器和当前状态更新在同一事务中；快照失败时整次保存失败，避免有状态无历史。
- 恢复确认框明确提示整站覆盖，但不要求再次输入密码。

## 测试与验证

- 云端单元测试：历史列表按版本倒序、最多 50 条、恢复 RPC 更新本地修订号。
- UI 测试：入口仅管理员可见、历史摘要正确、当前版本不可恢复、确认后才调用恢复。
- 失败测试：未登录、网络错误、快照不存在时保持当前页面数据不变。
- 数据库验证：连续保存 51 次后只保留 50 条；每个快照 revision 唯一；恢复后 revision 继续递增。
- 生产验证：在一个设备保存，在另一个设备查看对应版本并恢复；两个设备最终显示相同数据和“已同步”。

## 不在本次范围

- 手动命名版本。
- 比较两个版本的逐字段差异。
- 导出或下载历史快照。
- 只恢复单个班级或单个学员。
